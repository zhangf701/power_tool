# 预测算法与基础数据格式

本文档集中说明 PowerTool 中预测类功能的工程原理、算法流程和基础数据格式。它对应三个页面：**日前负荷预测**、**新能源预测**、**年度负荷预测**。前两个页面属于日前调度曲线预测，输出 24 小时或用户指定时长的 MW 曲线；年度负荷预测属于中长期规划估计，输出未来若干年的电量、最大负荷和典型负荷形态。

PowerTool 的预测模块定位为轻量级工程预测器。其目标不是替代调度主站、市场出清系统、完整气象数值预报或企业级负荷预测平台，而是在数据量有限、部署环境简单、需要快速解释的场景中给出可复核的预测曲线、误差量级和主要驱动因素。

## 1. 总体计算链路

日前预测的主流程如下：

1. 读取历史 CSV 或内置样例数据，统一映射为 `timestamp`、目标功率和气象字段。
2. 按预测对象选择目标变量：负荷使用 `load_mw`，光伏使用 `solar_mw`，风电使用 `wind_mw`。
3. 对缺失气象量进行补齐。优先使用历史同一时刻或同一小时的中位数；仍缺失时使用经纬度、海拔和气候板块形成的经验气象基线。若导入未来天气预报 CSV，预测日同时间戳的温度、GHI、风速会优先覆盖历史推断值；小时级天气会对 1–30 分钟预测点线性插值。
4. 构造特征向量，包括时刻周期项、星期/节假日、季节、经纬度、海拔、温度、GHI、风速、太阳高度角、太阳方位角、组件倾斜面辐照度 POA、入射角和组件几何参数。
5. 按用户选择运行单一算法，或运行自适应综合方案并在留出验证集上分配权重。
6. 根据历史残差形成 P10/P90 经验不确定性带。
7. 对新能源结果执行物理和运行约束后处理，例如装机容量裁剪、光伏夜间清零、光伏天气和组件温度修正、特殊事件修正。
8. 输出曲线、统计指标、算法误差表、驱动因素说明，并支持 JSON/CSV 导出。

年度负荷预测的主流程不同：它读取年度电量、最大负荷、GDP、人口和产业结构数据，采用趋势外推、弹性系数或综合法估计未来年度电量，再由负荷率、气候修正和同时率推算最大负荷，并生成春、夏、秋、冬典型 24 小时负荷形态。

## 2. 日前预测基础数据格式

### 2.1 内部标准行格式

日前负荷与新能源预测最终都会被整理为一组字典行。每一行代表一个历史采样点。

| 标准字段 | 类型 | 是否必需 | 单位 | 适用对象 | 说明 |
|---|---:|---:|---:|---|---|
| `timestamp` | 日期时间 | 是 | 本地标准时间 | 负荷、光伏、风电 | 采样点时间。程序不做时区换算，输入应保持同一地区、同一时间制度。 |
| `load_mw` | 数值 | 负荷预测必需 | MW | 负荷 | 历史实测或还原后的系统负荷、统调负荷、区域负荷。 |
| `solar_mw` | 数值 | 光伏预测必需 | MW | 光伏 | 历史光伏出力。夜间可为 0。 |
| `wind_mw` | 数值 | 风电预测必需 | MW | 风电 | 历史风电有功出力。 |
| `renewable_mw` | 数值 | 否 | MW | 新能源 | 若 CSV 中未提供而同时有 `solar_mw`、`wind_mw`，程序可由二者相加得到；但实际预测仍按光伏或风电独立建模。 |
| `temperature_c` | 数值 | 否 | ℃ | 负荷、光伏、风电 | 环境温度。缺失时程序自动推断。 |
| `ghi_wm2` | 数值 | 否 | W/m2 | 光伏、负荷辅助特征 | 水平面总辐照度。夜间应为 0；缺失时程序自动推断。 |
| `wind_speed_mps` | 数值 | 否 | m/s | 风电、负荷辅助特征 | 风速。缺失时程序自动推断。 |
| `cloud_cover_pct` | 数值 | 否 | % | 未来天气 CSV | 云量。若未来天气文件没有 GHI 但提供云量，程序会用云量修正推断 GHI。 |

经纬度、海拔、节假日国家、光伏组件倾角和方位角等不是历史 CSV 的核心字段，而是通过 `ForecastConfig` 或 GUI 参数输入控制。即使样例 CSV 中包含 `latitude`、`longitude`、`altitude_m`，当前通用 CSV 读取器也以页面/配置中的地理参数为准。

| `hour` | `hour`, `HE`, `hour_ending`, `OPR_HR`, `OPR_HOUR`, `小时` |
| `minute_offset` | `Tmstamp`, `minute`, `minutes`, `分钟`, `时刻`, `minute_offset` |
| `interval_index` | `period`, `point`, `point_index`, `interval`, `idx`, `序号`, `点号`, `时段`, `时点`, `96点` |
| `load_mw` | `load_mw`, `demand_mw`, `MW`, `SYS_FCST_ACT_MW`, `SYS_FCT_ACT_MW`, `total_load`, `load`, `负荷`, `统调负荷`, `系统负荷`, `电力负荷`, `实测负荷`, `样本负荷` |
| `solar_mw` | `solar_mw`, `solar`, `pv_mw`, `solar_power_mw`, `光伏`, `光伏功率`, `光伏出力`, `光伏发电` |
| `wind_mw` | `wind_mw`, `wind`, `wind_power_mw`, `Patv`, `active_power`, `风电`, `风电功率`, `风电出力`, `实际功率` |
| `renewable_mw` | `renewable_mw`, `renewables_mw`, `total_renewable_mw`, `renewable`, `ren_mw`, `新能源`, `新能源出力` |
| `temperature_c` | `temperature_c`, `temp_c`, `temperature`, `dry_bulb_c`, `T`, `气温`, `温度`, `环境温度` |
| `ghi_wm2` | `ghi_wm2`, `GHI`, `global_horizontal_irradiance`, `solar_irradiance`, `辐照度`, `总辐照`, `水平辐照` |
| `wind_speed_mps` | `wind_speed_mps`, `wind_speed`, `ws_mps`, `windspeed`, `Wspd`, `wind_mps`, `风速` |
| `cloud_cover_pct` | `cloud_cover_pct`, `cloud_cover`, `cloud`, `cloud_pct`, `clouds`, `total_cloud_cover`, `云量`, `云覆盖率` |

时间列支持四种常见写法。第一种是直接给出完整时间戳，例如 `2025-06-01 13:15`。第二种是 `日期 + 小时`，其中小时可以是 1–24 的 hour-ending 形式，程序会转为 0–23 的小时起点。第三种是 `日期 + 时段序号`，程序按 15 分钟间隔把 1–96 映射到全天 96 点。第四种是 `日期 + 分钟偏移` 或 `Day + Tmstamp`，例如风电比赛数据中的 `Day=1, Tmstamp=60` 表示样例起始日后第 60 分钟。

### 2.3 最小数据量和推荐数据量

程序硬性要求至少 48 个历史采样点。这个下限主要用于保证算法可以运行，不代表预测质量已经充分。实际使用时建议：

| 预测对象 | 最低可运行 | 工程推荐 | 说明 |
|---|---:|---:|---|
| 日前负荷 | 48 点 | 至少 4–8 周同粒度历史数据 | 需要覆盖工作日、周末、节假日和温度变化。 |
| 光伏日前 | 48 点 | 至少 2–8 周历史出力和辐照/温度数据 | 建议包含晴天、多云、阴天样本；只用出力也能运行，但物理解释会弱。 |
| 风电日前 | 48 点 | 至少数周风速与出力数据 | 风电对地形、机组状态和限电较敏感，短样本只能作为演示。 |
| 年度负荷 | 2 年 | 5 年以上年度电量、最大负荷、GDP 和人口数据 | 规划预测对历史趋势和产业结构输入敏感。 |

### 2.5 未来天气预报 CSV

日前负荷和新能源页面现在支持独立导入未来天气预报 CSV。该文件不需要包含 `load_mw`、`solar_mw` 或 `wind_mw` 等目标列，只用于给预测日提供外生气象驱动。GUI 中先导入训练 CSV 或选择内置数据集，再点击“导入未来天气CSV”，最后执行“预测”。

未来天气 CSV 至少需要时间列，以及 `temperature_c`、`ghi_wm2`、`wind_speed_mps`、`cloud_cover_pct` 中的一个字段。推荐格式如下：

```csv
timestamp,temperature_c,ghi_wm2,wind_speed_mps,cloud_cover_pct
2025-06-22 00:00,12.3,0,3.7,15
2025-06-22 01:00,12.0,0,3.9,15
2025-06-22 12:00,27.4,730,3.1,38
```

也可使用 `日期 + 小时`、`日期 + 时刻` 或 `date + time` 格式：

```csv
日期,小时,气温,总辐照,风速,云量
2025-06-22,1,12.3,0,3.7,15
2025-06-22,13,27.4,730,3.1,38
```

运行时，未来天气记录会按时间戳匹配预测点。若预测输出为 15 分钟而天气文件为小时级，程序在相邻天气点之间做线性插值；超出首尾天气点但距离不超过 6 小时的预测点使用邻近值。若某个气象字段缺失，则该字段仍回退到历史同刻统计和地理气候基线。对于光伏，导入的 GHI 会作为未来天气预期输入，再进入组件倾角/方位角、POA 和温度系数修正；若只提供云量而不提供 GHI，则程序会用云量对推断 GHI 进行经验衰减。

仓库内置样例为 `data/forecast_samples/future_weather_forecast_sample.csv`。

## 3. 日前预测特征工程

每个历史点和未来点都会转换为数值特征向量。主要特征包括：

- 时间周期项：小时角的一阶和二阶正弦/余弦、分钟归一化值，用于表示日内周期。
- 星期项：星期几的一阶正弦/余弦、周末标志、节假日标志。
- 季节项：由日期和纬度计算的季节值及其平方项，用于区分南北半球季节相位。
- 地理项：纬度、经度、海拔归一化值。
- 气象项：温度、温度二次项、GHI、风速。
- 太阳几何项：太阳高度角、太阳方位角、倾斜面辐照度 POA、入射角余弦、光伏相对功率修正系数。
- 组件几何项：光伏组件倾角、组件方位角的正弦/余弦。

缺失气象的补齐顺序为：未来天气 CSV（若已导入）、同一时刻中位数、同一小时中位数、全样本中位数、地理气候基线。地理气候基线会根据纬度、海拔、自动气候板块、日内温度波动和太阳日照因子估算温度、GHI 和风速。

节假日内置中国（`CN`）和美国（`US`）。其它地区可编辑 `data/forecast_holidays.json`，或通过 `ForecastConfig.holiday_config_path` 指定自定义节假日文件。

## 4. 日前预测算法

### 4.1 `adaptive_ensemble`：自适应综合方案

这是默认算法。为保持轻量启动和稳定回归，默认候选算法集为 Huber 鲁棒回归、岭回归、相似日同刻法、同刻指数平滑和周周期基准；scikit-learn 树模型仍作为可选算法保留，但不再作为默认候选。若历史数据足够，程序取最后一段数据作为验证集；验证集长度由配置中的 `validation_min_points` 和 `validation_fraction` 控制，默认约为历史数据的 20%，但会保留至少 24 点训练数据。

### 4.2 `sklearn_auto`：scikit-learn 自动引擎

这是可选算法。程序在进入该算法时才延迟导入 scikit-learn，先尝试梯度提升树，再尝试随机森林。若树模型训练失败，则返回不可用并由上层流程回退。

- 梯度提升树参数：`n_estimators=24`，`max_depth=2`，`learning_rate=0.08`，`random_state=42`。
- 随机森林参数：`n_estimators=12`，`max_depth=6`，`min_samples_leaf=2`，`random_state=42`，`n_jobs=1`。

该模式适合轻量级非线性拟合，能够处理温度、辐照、风速与负荷/出力之间的非线性关系。代价是可解释性弱于线性模型，且对历史样本覆盖范围敏感。

每个可用算法在验证集上计算 MAE。权重按误差平方反比分配：

```text
w_i = (1 / max(MAE_i, ε)^2) / Σ_j(1 / max(MAE_j, ε)^2)
```

综合预测为各算法预测的加权和。该方法适合工程快算，因为它不会预设某一个模型总是最好，而是让最近历史验证结果决定权重。

### 4.3 `ridge`：岭回归

岭回归先对特征列按标准差缩放，然后求解：

```text
β = (XᵀX + λI)^+ Xᵀy
ŷ = X_future β
```

其中 `+` 表示伪逆，默认正则化系数约为 0.25。岭回归的优势是稳定、快速、可作为回退基线；不足是对强非线性和突变事件的刻画能力有限。

### 4.4 `huber`：两阶段 Huber 权重岭回归

Huber 方案先用岭回归得到初始残差 `r`，再用残差中位数估计尺度：

```text
s = 1.4826 × median(|r|) + ε
```

权重按 Huber 影响函数给出：

```text
weight = 1,                       |r| ≤ 1.35s
weight = 1.35s / max(|r|, ε),      |r| > 1.35s
```

最后进行加权岭回归。该方法对坏点、临时尖峰和局部异常更稳健，适合作为负荷数据未充分清洗时的基准模型。

### 4.5 `hourly_analog`：相似日同刻法

相似日同刻法只在历史同一时刻或同一小时中找候选样本，并按以下因素打分：

- 温度差、GHI 差、风速差形成的气象距离。
- 工作日/周末/节假日类型是否一致。
- 星期几是否一致。
- 历史样本距预测时刻的时间间隔。

程序取分数最低的最多 8 个样本，并按 `1 / (0.08 + score)` 加权平均。该方法便于调度员理解，适合节假日、特殊日和人工经验校核。

### 4.6 `exp_smoothing`：同刻指数平滑

该方法对同一时刻的历史值做指数平滑。历史样本不少于 5 个时使用 `α=0.35`，样本较少时使用 `α=0.55`。它偏重近期趋势，计算量很小，适合负荷还原修正后快速形成基准曲线。

### 4.7 `seasonal_naive`：周周期基准

周周期基准优先使用上一周同一时刻的值；缺失时使用前一日同一时刻；仍缺失时使用同一时刻或同一小时的历史中位数。它不追求最优精度，但适合作为模型失效时的安全基线。

## 5. 新能源预测的物理约束

新能源预测只支持两种独立资源：`solar`/`光伏` 和 `wind`/`风电`。程序不把光伏和风电聚合成一个新能源目标变量进行预测，避免混合资源掩盖不同物理规律。

### 5.1 光伏预测

光伏预测在机器学习输出之后继续执行太阳位置和组件几何修正。太阳位置使用日期、经纬度、名义时区、时差方程、太阳赤纬和时角估算太阳高度角与方位角。GHI 经过天气系数修正，天气类型包括晴空、少云、多云、阴天、雨雪和雾霾；云量和人工辐照修正系数会进一步影响 GHI。

倾斜面辐照度 POA 由三部分组成：

```text
POA = POA_direct + POA_diffuse + POA_ground
```

其中直射分量由 DNI 和入射角余弦得到，散射分量采用各向同性近似，地面反射分量由 GHI、反照率和组件倾角得到。组件温度按 NOCT 近似：

```text
T_cell = T_ambient + (NOCT - 20) / 800 × POA
```

相对功率修正系数由 POA 相对晴空水平面参考值与温度折减共同构成。太阳高度角小于 0° 时，光伏预测值、P10 和 P90 均强制为 0。

### 5.2 风电预测

风电预测使用风速、时刻、季节、地理和气候特征进行数据驱动预测。当前轻量级实现没有内置详细风机功率曲线、空气密度修正、尾流模型或限电识别模型；如果存在弃风、限电或机组检修，应通过清洗历史数据或特殊事件配置进行修正。

### 5.3 装机容量与特殊事件

若 `ForecastConfig.renewable_capacity_mw` 大于 0，新能源预测会被裁剪到 `[0, 装机容量]`。特殊事件可通过 `data/forecast_builtin_config.json` 配置，支持绝对 MW 修正和相对比例修正，并可设置开始时间、结束时间、爬坡时间和滞后时间。

## 6. 不确定性区间与统计量

日前预测的 P10/P90 是经验残差带，不是严格概率校准后的分位数预测。程序在验证集或训练拟合残差上取残差绝对值的指定分位数，默认使用配置中的 `confidence_quantile=0.80`，同时设置至少为平均目标值 3% 的下限。输出统计量包括峰值、谷值、峰谷差、平均值、负荷率或容量因子、最大上爬坡、最大下爬坡和日电量/发电量。

## 7. 年度负荷预测数据格式

年度负荷预测使用 JSON 数据集。内置样例为 `data/annual_load_forecast_sample.json`。基本结构如下：

```json
{
  "name": "区域年度负荷规划样例",
  "source": "数据来源说明",
  "region": "区域名称",
  "latitude": 31.85,
  "longitude": 118.92,
  "climate_block": "华东湿润夏热冬冷气候区",
  "base_year": 2025,
```

## 8. 年度负荷预测算法

年度模块提供三种方法。

### 8.1 趋势外推法

趋势外推法同时计算历史 CAGR 和年度线性趋势，并进行加权：

```text
E_trend = 0.55 × E_CAGR + 0.45 × E_linear
```

这样可以降低单一年份波动对长期外推的影响。

### 8.2 弹性系数法

先用历史用电量 CAGR 与 GDP CAGR 估计电量/GDP 弹性，并将弹性限制在 0.45–1.35 范围内。宏观增长率由 GDP、人口和产业结构增长加权形成：

```text
sector_growth = 0.08 × primary + 0.58 × secondary + 0.34 × tertiary
macro_growth  = 0.65 × gdp + 0.20 × sector_growth + 0.15 × population
policy_growth = dual_carbon + electrification
energy_growth = max(-2%, elasticity × macro_growth + policy_growth)
```

未来电量按基准年电量逐年递推。

### 8.3 综合法

综合法采用：

```text
E = 0.45 × E_trend + 0.55 × E_elasticity
```

它是当前规划页默认方法，适合在既有历史趋势、又有宏观和政策输入时使用。

最大负荷由两路估计综合得到：一路由预测电量和负荷率换算，另一路由历史最大负荷增长率、弹性增长、气候峰值附加量和同时率修正得到。最终最大负荷取两者加权，并给出随规划年限扩大的 P10/P90 不确定性带。

## 9. 输出数据结构

日前预测输出中的每个点包含：

| 字段 | 含义 |
|---|---|
| `timestamp` | 预测点时间。 |
| `value_mw` | 点预测值。 |
| `p10_mw`, `p90_mw` | 经验不确定性下、上界。 |
| `temperature_c`, `ghi_wm2`, `wind_speed_mps` | 该点使用的气象驱动量。 |
| `drivers` | 文本化驱动因素说明。 |
| `poa_wm2`, `solar_altitude_deg`, `solar_azimuth_deg`, `incidence_angle_deg` | 光伏相关太阳几何与辐照量。 |
| `weather_factor`, `pv_power_factor` | 天气和组件相对功率修正系数。 |

年度预测输出包含逐年电量、最大负荷、P10/P90 区间、负荷率，以及按年份缩放的春夏秋冬 24 小时典型负荷形态。

## 10. 数据质量和使用边界

为了让轻量级预测结果具有工程意义，建议在使用前至少核查以下事项：

- 负荷数据是否为实测负荷、还原负荷或预测负荷，三者不要混用。
- 是否存在限电、拉闸、需求响应、检修、极端天气等非自然样本；必要时应剔除或用特殊事件配置处理。
- 采样间隔是否一致；混合 5 分钟、15 分钟和小时数据会降低同刻模型质量。
- 单位是否统一为 MW、℃、W/m2、m/s。
- 时间戳是否存在夏令时、跨时区或 hour-ending/hour-beginning 混淆。
- 光伏和风电不要作为一个聚合目标训练；应分别预测后再按工程需要合成。
- 年度预测结果应与用户报装、重点产业项目、城市规划、能源规划和历史最大负荷形成校核闭环。

## 11. 作为轻量级 APP 的后续改进建议

当前预测模块已经具备离线样例、CSV 表头兼容、算法集成、物理后处理和导出能力。若继续按轻量级桌面 APP 演进，建议优先改进以下方面：

1. **保持 GUI 拆分边界**：`power_tool_gui.py` 现在作为主窗口壳，通用服务、动态稳定、参数与短路、合环、预测和录波页面已经迁入各自 mixin 模块；后续修改应继续避免把页面专属逻辑重新堆回主壳。
2. **预测数据校验前置**：增加导入前预检报告，明确显示识别到的时间列、目标列、天气列、缺失率、采样间隔、重复点和单位风险。
3. **未来天气质量检查**：未来天气 CSV 已可导入，后续应增加覆盖率、时间范围、小时起止、GHI 夜间非零、风速异常等专项校验。
4. **轻量打包清理**：发布包不应包含 `__pycache__`、临时文件和测试缓存；可增加打包脚本自动清理。
5. **预测结果复盘闭环**：增加“导入实际值—自动计算 MAE/RMSE/MAPE—沉淀本地误差库”的页面，提高长期使用价值。
6. **配置版本化**：对 `forecast_builtin_config.json`、节假日、特殊事件和区域配置增加 schema 校验与版本提示，减少用户误改 JSON 后的隐性错误。
7. **可解释性增强**：对树模型增加特征贡献或敏感性摘要，至少输出温度、GHI、风速、节假日、时刻等关键驱动量的相对影响。
8. **年度预测边界增强**：年度模块可增加分区负荷、产业项目清单和用户报装容量输入，但仍应保持“规划快算”定位，不宜演化成重型空间负荷预测平台。
